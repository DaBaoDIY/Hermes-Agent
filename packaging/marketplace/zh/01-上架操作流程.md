# Hermes Agent 上架 AWS Global Marketplace 操作流程

本文档用于指导将 **Hermes Agent on Rocky Linux** 以 **AMI with CloudFormation** 交付方式上架到 AWS Global Marketplace。

| 项目 | 值 |
|:---|:---|
| Seller AWS Account | `249583190302` |
| AMI ID | `ami-09f49fe6148baa5f0` |
| 源区域 | `us-east-1` |
| 产品类型 | AMI with CloudFormation |
| 定价建议 | Free software，客户仅支付 AWS 基础设施费用 |

## 1. 上架目标架构

上架交付方式建议使用 **AMI + CloudFormation**：

```text
AWS Marketplace
  -> Buyer subscribes
  -> CloudFormation deployment option
  -> EC2 Rocky Linux instance
  -> Hermes Agent Web UI
  -> EC2 IAM Role invokes Amazon Bedrock
```

核心 AWS 服务：

- Amazon EC2：运行 Hermes Agent。
- Amazon Bedrock：默认模型推理服务。
- AWS IAM：EC2 Instance Profile 最小权限调用 Bedrock。
- AWS Systems Manager：获取 setup token、Session Manager 运维。
- Amazon VPC / Security Group：控制访问边界。
- 可选：API Gateway、NAT Gateway、CloudWatch、Secrets Manager。

## 2. 前置条件

### 2.1 AWS 账号与权限

确认本地 Mac 已配置 AWS CLI，且 AK/SK 对应账号为：

```text
249583190302
```

验证命令：

```bash
aws sts get-caller-identity
```

返回结果中的 `Account` 必须是 `249583190302`。

### 2.2 Seller 注册

进入 AWS Marketplace Management Portal：

```text
https://aws.amazon.com/marketplace/management/
```

确认：

- 已注册为 Marketplace Seller。
- 免费产品模式可先跳过银行/税务资料，但 AWS 控制台如提示补全资料，则按提示完成。
- Partner Central 账号已关联 Seller AWS 账号，后续 PRM 需要。

### 2.3 AMI 要求

Marketplace AMI 基本要求：

- AMI 必须在 `us-east-1`。
- HVM。
- EBS-backed。
- Root snapshot 不加密。
- 不包含 AWS AK/SK、API Key、测试 token、SSH authorized keys。
- 每个客户实例首次启动都要重新生成 setup token。

检查 AMI：

```bash
aws ec2 describe-images \
  --region us-east-1 \
  --image-ids ami-09f49fe6148baa5f0 \
  --query 'Images[0].{ImageId:ImageId,Name:Name,Architecture:Architecture,VirtualizationType:VirtualizationType,RootDeviceType:RootDeviceType,State:State,BlockDeviceMappings:BlockDeviceMappings}' \
  --output table
```

如果发现 snapshot 加密，需要重新制作未加密快照的 AMI。

## 5. Marketplace Ingestion Role

AWS Marketplace 需要一个角色读取 AMI 和 snapshot。

脚本会自动创建该角色：

```text
AwsMarketplaceAmiIngestion
```

如果手动创建，信任策略为：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "assets.marketplace.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

权限策略为：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:ModifyImageAttribute",
        "ec2:DescribeImages",
        "ec2:ModifySnapshotAttribute",
        "ec2:DescribeSnapshots"
      ],
      "Resource": "*"
    }
  ]
}
```

## 6. 首次创建 Draft 产品

如果还没有 Marketplace `Product ID`，使用首次创建脚本。

```bash
cd "/Users/yebaoxu/Documents/Hermes-Agent on Rocky Linux"

SELLER_ACCOUNT_ID=249583190302 \
AMI_ID=ami-09f49fe6148baa5f0 \
VERSION_TITLE=v1.0.0 \
MARKETPLACE_REGIONS=us-east-1 \
MARKETPLACE_INSTANCE_TYPES=t3.small,t3.medium,m6i.large \
RECOMMENDED_INSTANCE_TYPE=t3.small \
MARKETPLACE_OS_NAME=CENTOS \
packaging/marketplace/scripts/submit-marketplace-draft-product.sh
```

如果 `MARKETPLACE_OS_NAME=CENTOS` 仍被校验拒绝，可将这一项改为 `RHEL` 后重试。

脚本会执行：

1. 校验当前 AWS Account。
2. 校验 AMI 信息。
3. 校验 CloudFormation 模板。
4. 创建或复用 `AwsMarketplaceAmiIngestion`。
5. 创建公开 S3 资产桶。
6. 上传 CloudFormation、架构图、Logo、使用说明。
7. 调用 Marketplace Catalog API 创建 Draft AMI Product。
8. 创建 Draft Offer。
9. 提交 CloudFormation Delivery Option。

成功后会返回 `ChangeSetId`。

查看状态：

```bash
aws marketplace-catalog describe-change-set \
  --catalog AWSMarketplace \
  --change-set-id <CHANGE_SET_ID> \
  --region us-east-1 \
  --query '{Status:Status,FailureCode:FailureCode,FailureDescription:FailureDescription,Changes:ChangeSet[].{ChangeName:ChangeName,ChangeType:ChangeType,Entity:Entity,Errors:ErrorDetailList}}'
```

状态流转：

```text
PREPARING -> APPLYING -> SUCCEEDED / FAILED
```

如果 API 因字段校验失败，建议进入 Marketplace Management Portal 手动创建 Draft Product，然后使用第 7 节脚本追加版本。

## 8. Management Portal 手动提交路径

如果你选择在控制台手动上架：

1. 打开 AWS Marketplace Management Portal。
2. Products -> Server products -> Create server product。
3. Product type 选择 AMI。
4. Delivery method 选择 CloudFormation template。
5. 填写产品信息：
   - Product title: `Hermes Agent on Rocky Linux`
   - Short description: 参考 `03-产品文案-中文版.md`
   - Long description: 参考 `03-产品文案-中文版.md`
   - Logo: `assets/hermes-agent-logo.png`
   - Architecture diagram: `assets/hermes-agent-architecture.png`
6. 填写 AMI 信息：
   - Region: `us-east-1`
   - AMI ID: `ami-09f49fe6148baa5f0`
   - OS user: `rocky`
   - OS: Rocky Linux 9 x86_64
7. 填写 CloudFormation 模板 URL：
   - 上传 `cloudformation/hermes-agent-marketplace.yaml` 到公开 S3。
8. 选择免费软件定价。
9. 提交审核。

## 9. Limited 状态测试

首次通过审核后，产品通常为 Limited 状态。

在 allowlist 买家账号中测试：

1. 订阅产品。
2. 通过 CloudFormation delivery option 部署。
3. 等待 Stack 进入 `CREATE_COMPLETE`。
4. 查看 CloudFormation 输出：
   - `WebUrl`
   - `SetupTokenCommand`
   - `InstanceId`
5. 获取 setup token：

```bash
aws ssm send-command \
  --region <REGION> \
  --instance-ids <INSTANCE_ID> \
  --document-name AWS-RunShellScript \
  --parameters commands='sudo cat /etc/hermes-agent/setup-token'
```

6. 浏览器访问 `WebUrl`。
7. 输入 setup token。
8. 测试 Bedrock 模型调用。

## 10. PRM 验证

### 10.1 Marketplace Metering

通过 Marketplace 订阅流程启动的 EC2 应自动带 ProductCode。

```bash
aws ec2 describe-instances \
  --instance-ids <INSTANCE_ID> \
  --query 'Reservations[0].Instances[0].ProductCodes'
```

### 10.2 Resource Tagging

CloudFormation 模板中支持 `ProductCode` 参数。拿到 Marketplace Product Code 后，部署时填写该值。

标签格式：

```text
aws-apn-id=pc:<PRODUCT_CODE>
```

验证：

```bash
aws resourcegroupstaggingapi get-resources \
  --tag-filters Key=aws-apn-id,Values=pc:<PRODUCT_CODE>
```

### 10.3 Bedrock User Agent

Hermes Agent 会读取：

```text
/etc/hermes-agent/aws-sdk.env
```

内容格式：

```text
AWS_SDK_UA_APP_ID=APN_1.1/pc_<PRODUCT_CODE>$
```

触发一次 Bedrock 测试后，等待 5-15 分钟，在 CloudTrail 中查看：

```bash
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=Converse \
  --max-results 10
```

确认 UserAgent 中包含 `APN_1.1` 和 product code。

## 12. 版本更新

Marketplace 每个版本需要不同 AMI ID。

如果 AMI 内容不变但模板有更新，也需要复制 AMI：

```bash
aws ec2 copy-image \
  --region us-east-1 \
  --source-region us-east-1 \
  --source-image-id ami-09f49fe6148baa5f0 \
  --name "hermes-agent-rocky-v1.0.1-$(date +%Y%m%d)"
```

然后用新 AMI ID 运行：

```bash
PRODUCT_ID=prod-xxxxxxxxxxxx \
AMI_ID=<NEW_AMI_ID> \
VERSION_TITLE=v1.0.1 \
packaging/marketplace/scripts/submit-marketplace-version.sh
```

## 13. 常见失败与处理

| 问题 | 可能原因 | 处理方式 |
|:---|:---|:---|
| `SCAN_ERROR` | AMI 内有敏感信息、UserData 风险命令、系统安全项不合规 | 重新运行 cleanup，确认无 `curl`、密钥、token、日志 |
| `DUPLICATE_AMI_ID` | 同一 AMI 已用于其他 Marketplace 版本 | `copy-image` 生成新 AMI ID |
| `VALIDATION_ERROR` | Catalog API 字段或 CloudFormation 模板不符合要求 | 查看 `ErrorDetailList`，优先用控制台补字段 |
| 找不到 AMI | AMI 不在 `us-east-1` 或账号不对 | 确认 Region 和 AWS Account |
| Bedrock 测试失败 | 模型未开通、Region 不一致、IAM 权限不足 | 开通 Bedrock model access，检查 IAM Role |
| 无法访问 Web UI | 安全组 CIDR 不对或服务未启动 | 检查 `AllowedWebCidr`、`systemctl status hermes-agent` |

## 14. 建议操作顺序

建议你按这个顺序执行：

1. `aws sts get-caller-identity` 确认账号。
2. `describe-images` 检查 AMI。
3. `validate-template` 检查 CloudFormation。
4. 跑 `submit-marketplace-draft-product.sh`。
5. 记录返回的 `ChangeSetId`。
6. `describe-change-set` 观察状态。
7. 进入 Marketplace Portal 补齐价格、EULA、可见性等字段。
8. Limited 测试。
9. 验证 PRM。
10. 申请 Public。
