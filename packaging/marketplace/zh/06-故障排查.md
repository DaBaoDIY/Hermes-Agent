# Hermes Agent Marketplace 上架故障排查

---

## 1. AWS CLI 账号不对

现象：

```text
Current AWS account is xxxxxxxxxxxx, expected 249583190302.
```

处理：

```bash
aws configure list
export AWS_PROFILE=<your-profile>
aws sts get-caller-identity
```

确认返回：

```text
Account: 249583190302
```

---

## 2. AMI 不存在或区域错误

现象：

```text
InvalidAMIID.NotFound
```

处理：

```bash
aws ec2 describe-images \
  --region us-east-1 \
  --image-ids ami-09f49fe6148baa5f0
```

确认：

- AMI 在 `us-east-1`。
- AMI 属于当前 Seller 账号。
- AMI state 为 `available`。

---

## 3. AMI Snapshot 加密

Marketplace 通常不接受加密 root snapshot。

检查：

```bash
aws ec2 describe-images \
  --region us-east-1 \
  --image-ids ami-09f49fe6148baa5f0 \
  --query 'Images[0].BlockDeviceMappings'
```

如果 snapshot 加密，需要重新制作未加密 AMI。

---

## 4. CloudFormation validate-template 失败

命令：

```bash
aws cloudformation validate-template \
  --region us-east-1 \
  --template-body file://packaging/marketplace/cloudformation/hermes-agent-marketplace.yaml
```

如果失败：

1. 先看 YAML 语法：

```bash
ruby -e 'require "yaml"; YAML.load_file("packaging/marketplace/cloudformation/hermes-agent-marketplace.yaml"); puts "ok"'
```

2. 检查 CloudFormation intrinsic function 是否写法正确。
3. 检查 `AmiId` 参数是否存在。

## 5. Marketplace Catalog API `VALIDATION_ERROR`

查看错误：

```bash
aws marketplace-catalog describe-change-set \
  --catalog AWSMarketplace \
  --change-set-id <CHANGE_SET_ID> \
  --region us-east-1 \
  --query '{Status:Status,FailureCode:FailureCode,FailureDescription:FailureDescription,Changes:ChangeSet[].{ChangeName:ChangeName,ChangeType:ChangeType,Entity:Entity,Errors:ErrorDetailList}}'
```

常见原因：

| 错误 | 处理 |
|:---|:---|
| `REGION_NOT_AVAILABLE` | 先为产品提交 `AddRegions`；脚本默认用 `MARKETPLACE_REGIONS=us-east-1` 添加 |
| `INVALID_OPERATING_SYSTEM_NAME` | Marketplace OS 名称必须使用受支持枚举；Rocky Linux 可先试 `MARKETPLACE_OS_NAME=CENTOS`，如果仍失败再试 `MARKETPLACE_OS_NAME=RHEL` |
| `RECOMMENDED_INSTANCE_TYPE_NOT_AVAILABLE` | 推荐实例类型必须先加入产品可用实例类型；脚本默认提交 `MARKETPLACE_INSTANCE_TYPES=t3.small,t3.medium,m6i.large` |
| 字段名不被接受 | 使用 Marketplace Portal 手动创建产品，再用版本脚本提交 delivery option |
| 缺少 EULA | 控制台补 EULA 或选择标准合同 |
| 缺少价格项 | 控制台设置 Free software |
| 缺少 Support 信息 | 控制台补支持 URL/邮箱 |
| ArchitectureDiagram 不合法 | 使用 PNG，公开 HTTPS URL |

## 6. Marketplace `SCAN_ERROR`

常见原因：

- AMI 中包含 setup token。
- AMI 中包含 AWS AK/SK 或 API key。
- SSH authorized keys 未清理。
- firstboot/UserData 中存在高风险命令。
- root login 或系统安全配置不符合要求。
- 日志、history、临时文件未清理。

处理：

1. 在源实例上运行：

```bash
sudo /opt/hermes-agent/packaging/marketplace/scripts/ami-cleanup.sh
```

或使用项目中的脚本：

```bash
sudo bash packaging/marketplace/scripts/ami-cleanup.sh
```

2. 重新创建 AMI。
3. 确认 `packaging/scripts/hermes-agent-firstboot` 中不使用 `curl`。
4. 重新提交。

## 7. `DUPLICATE_AMI_ID`

原因：

同一个 AMI ID 已用于 Marketplace 其他版本。

处理：

```bash
aws ec2 copy-image \
  --region us-east-1 \
  --source-region us-east-1 \
  --source-image-id ami-09f49fe6148baa5f0 \
  --name "hermes-agent-rocky-v1.0.1-$(date +%Y%m%d)"
```

使用新 AMI ID 重新提交。

## 8. CloudFormation Stack 创建失败

检查：

```bash
aws cloudformation describe-stack-events \
  --stack-name <STACK_NAME> \
  --region <REGION> \
  --max-items 20
```

常见原因：

- `AllowedWebCidr` 格式错误。
- `AvailabilityZone` 与实例类型不匹配。
- IAM capability 未勾选。
- 账号 EC2 配额不足。
- AMI 未被 Marketplace 正确映射到当前 Region。

---

## 9. Web UI 无法访问

检查：

```bash
sudo systemctl status hermes-agent
sudo ss -lntp | grep 8080
sudo hermes-agent-ctl logs
```

AWS 侧检查：

- Security Group 是否允许你的公网 IP 访问 `TCP 8080`。
- NACL 是否放通。
- 实例是否有 Public IP。
- 本地网络是否阻断 8080。

---

## 10. Bedrock 测试失败

检查：

- Bedrock 模型是否在当前 Region 开通。
- Web UI 配置的 AWS Region 是否正确。
- 模型 ID 或 inference profile ID 是否正确。
- EC2 IAM Role 是否包含 Bedrock 权限。
- 实例是否有出站 HTTPS。

日志：

```bash
sudo hermes-agent-ctl logs
```

---

## 11. PRM User Agent 不出现

检查：

```bash
sudo cat /etc/hermes-agent/aws-sdk.env
sudo systemctl restart hermes-agent
sudo systemctl show hermes-agent --property=Environment
```

触发一次 Bedrock 调用后等待 5-15 分钟，再查 CloudTrail。

如果仍没有：

- 确认 Product Code 不是 Product ID。
- 确认格式为 `APN_1.1/pc_<PRODUCT_CODE>$`。
- 确认 Hermes Agent 调用的是 Bedrock provider。
